# 搜索名称行情覆写：池快照的新鲜度与展示解耦

日期：2026-11-16　状态：已采纳（主人报「搜索 518850 显示『黄金9999』而面板显示『黄金ETF华夏』」驱动；数据侧口径修订见 §12.59，本 ADR 治其根因类）

池（data/*.json）随插件版本分发的静态快照，其名称权威性曾直接泄漏到搜索展示：两次发版之间，改名、XD/XR/DR 除息日戳、ETF 简称口径（§12.59：上证 ETF 官方场内简称 948/948 与行情商展示名不一致）都会以旧貌示人，而每次修正都要走 bump → publish → 用户升级的完整发版链。目标排序沿用 ADR-0006（可靠覆盖 > 一致性 > 维护成本 > 速度）：名称的「一致性」不该由池的「可靠覆盖」职责代偿。

**决定**：`search(market, query, { chain })` 在返回前对 `source === "pool"` 行（截断后 ≤30 个代码）批量过 `chain.runChain(market, "snap", codes)`，取到有效快照（price > 0）即以行情名覆盖池名——**搜索名 ≡ 添加后面板名 by construction**。行情链不可用 → 保留池名（fail-open，不新增错误标记：覆写是展示增强，池名兜底 = 既有行为）。catalog/smartbox 行不参与（名称本就地新鲜）。覆写与面板快照共用同一 gate（ADR-0007）：TTL 10s、在途合并、退避期回陈旧缓存，自选内代码搜索时命中温缓存，上游增量趋近于零。池的新定位随之收窄：**候选名单 + 全网不可达时的离线兜底**——名称不再由池承担，刷新节奏维持「季度例行 + 异常触发」，名称类问题从此不触发发版。

## Considered Options

- **运行时自动刷池（把生成器搬进插件定时跑）**：拒绝——生成器是 173 批次报价校验 + 3MB 港交所 xlsx 对账的 fail-closed 重作业，运行时养不起；上游失败模式翻倍，违背「池 = 已验证快照」哲学（data/README.md）。
- **独立数据通道（插件定期从 npm latest / GitHub raw 拉新池，数据与代码解耦发版）**：拒绝——引入「半新池 × 半旧代码」版本错配与分发通道可靠性问题；名称腐烂已由覆写根治，剩余收益（候选名单新鲜度）<5%。
- **纯代码泛查必问 smartbox（原 L2 设想：治「新上市搜不到」）**：TDD 前证伪——新上市按全码/名称搜索今天已可达（池 0 命中 → 池<30 补问，§12.39 口径 + 回归钉）；唯一残余缺口是**前缀泛查**（如「300」被 ≥30 条池命中淹没，池外新号段排不进前 30），补全需 smartbox 行同分前置或配额制——牺牲浏览期熟name排序换长尾发现，UX 取舍不成立，记录后暂缓（回归钉：tests/search-index.test.mjs「新上市按全码可搜」）。
- **退市残留运行时拦截（搜索拒显冻结价码）**：不新增——ADR-0006 已拒（误伤长期停牌复牌标的）；添加路径的行情校验（resolveDirect）仍是最终防线。

## Consequences

- 每次 cn/hk 搜索（带 chain）多一次批量快照请求；10s TTL + 在途合并 + 与面板共享 gate 下，重复搜索与自选交集请求为零增量；最坏情况搜索响应被 provider 超时拖慢，退避后快速失败自愈。
- 行情链全挂时搜索回落池名（= §12.59 前行为），名称可能带 XD 日戳等池态——已知的离线降级形态，不标错。
- client 零改动（rows.name 字段原样消费），`lib/client.js` 无 diff；`search()` 无 chain 调用方（既有测试、潜在脚本）行为不变。
- 修订 ADR-0006 的「池优先」语义：池仍决定候选与排序，名称展示权移交行情链；与 ADR-0007 无冲突（覆写是其第四个消费者，与 resolveDirect/批量快照同 gate）。
- 探针纪律：覆写测试的 smartbox 夹具名必须 ASCII（UTF-8 中文经 GBK 解码字节错位会吞 `~` 分隔符，见 tests/search-index.test.mjs 注记与 L222 先例）。
